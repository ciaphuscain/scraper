# Engineering decisions

1. **SQLite + WAL, YouTube IDs as primary keys.** Stable IDs make directory names collision-free and make
   re-discovery idempotent. WAL + `busy_timeout` lets the API and worker processes share the DB; a small
   retry wrapper handles residual "database is locked" errors.
2. **Job queue in SQLite, not Celery/Redis.** Atomic `UPDATE … RETURNING` claim; a partial unique index on
   `dedupe_key` for active statuses prevents duplicate work per video+stage. Lanes (`network`, `cpu`, `llm`,
   `general`) run as threads inside one worker process; a file lock enforces one worker per archive.
3. **Heavy-work exclusivity.** Whisper and Ollama share a lock unless `allow_parallel_heavy` is enabled,
   matching the 16 GB / CPU-only target. Defaults: 2 network, 1 CPU, 1 LLM job.
4. **Retry policy.** Transient errors (network, 429, bot-check, timeouts, invalid AI JSON) retry with
   exponential backoff up to `max_retries`. Permanent errors (private, removed, age/region restricted,
   members-only) fail immediately and are skipped by "retry failed" unless explicitly included. Ollama being
   offline *defers* the job (no attempt consumed). Interrupted jobs are requeued without consuming an
   attempt and keep their checkpoint.
5. **No access-control bypass.** Age gates, login walls, bot checks and region locks are reported, never
   circumvented. A global rate limiter spaces YouTube requests (default 2 s) and backs off after throttling.
6. **Caption choice.** Creator captions → original-language auto captions → Whisper. Auto-translated tracks
   are never used because they are not the spoken content.
7. **Rolling-caption cleanup only when detected.** Line de-duplication against the previous cue is applied
   only when the YouTube rolling pattern is detected, so repeated speech in normal captions is preserved.
8. **Completeness label is conservative.** For captions it is based on timestamp coverage of the video
   duration (≥85 % or ≤30 s gap = complete). This cannot detect untranscribed speech inside the covered range;
   that limitation is documented in `transcript_metadata.json`.
9. **Ideas are evidence-first.** The model must cite segment IDs; invalid references are discarded; excerpts
   must appear verbatim (normalised) in the transcript or are replaced with real segment text; timestamps are
   computed from segments. Ideas without any valid source are dropped and counted in validation stats.
10. **Dedupe is conservative.** Near-identical pairs merge automatically; borderline pairs merge only when the
    LLM confirms equivalence (bounded to 60 checks per video). Ideas from the same chunk are not merged unless
    titles are identical. Merges union all sources.
11. **User annotations are separate.** Notes/tags/bookmarks live in `idea_annotations` and are re-linked
    after re-analysis by title match or segment overlap; unmatched notes stay visible on the video page.
12. **Reports are deterministic first.** All aggregates are computed from stored ideas; the optional LLM
    narrative must cite idea IDs and uncited statements are dropped. Cross-channel pairs come from lexical
    candidates (inverted index, not O(n²)) and are only labelled same/similar/contradictory after LLM
    validation.
13. **Prompts are versioned rows.** Editing creates a new version; reset creates a new version with the
    default text. Each analysis stores the versions used.
14. **Database path vs output directory.** The DB location is fixed by env (`YTCS_ARCHIVE_DIR`) because it
    must be known before settings can be read; the Output directory setting controls archive files/exports.
15. **Frontend**: shadcn-style components are written in-repo (Radix primitives + Tailwind v4) rather than
    generated by the shadcn CLI. Long lists (transcripts, ideas) are virtualised.
